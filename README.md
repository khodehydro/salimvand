# فروشگاه سلیم وند

Monorepo سامانهٔ کاتالوگ قطعات خودرو و ERP فروشگاه آذین خودرو سلیم وند در میاندوآب.

## وضعیت فعلی پروژه

این مخزن در حال تکمیل نهایی است. زیرساخت Monorepo، API، مدل داده، احراز هویت، کاتالوگ اولیه، موجودی، فاکتور، رسانه، پنل پایه و Deploy عملیاتی وجود دارد؛ اما وجود کد یا Build موفق به‌تنهایی به معنی تکمیل محصول مطابق سند مرجع نیست.

مواردی که هنوز باید در Audit و اجرای نهایی تأیید و تکمیل شوند: انطباق کامل UI با Design System و صفحات مرجع، گردش‌کارهای واقعی CMS، تست‌های E2E و Integration، پوشش کامل نقش‌ها و مجوزها، دادهٔ واقعی کاتالوگ، SEO همهٔ موجودیت‌های قابل ایندکس، و Acceptance Criteria تحویل.

هر قابلیت در گزارش تحویل با یکی از وضعیت‌های «اسکلت کد»، «پیاده‌سازی کاربردی»، «آمادهٔ Production» یا «تکمیل مطابق سند» علامت‌گذاری می‌شود؛ ادعای تکمیل ۱۰۰٪ بدون اجرای این تطبیق پذیرفته نیست.

## اجزای پروژه

- `apps/api`: NestJS، Auth، Role Guard، Catalog، Inventory، Media، Dashboard و Health probes
- `apps/website`: Next.js، سایت عمومی RTL، صفحات محصول، دسته‌بندی، خودرو، موقعیت محلی، Sitemap و مسیر خصوصی فاکتور
- `apps/admin`: React + Vite، پنل مدیریت، ورود، نقش‌ها، محصولات، انبار، رسانه، داده‌های مرجع و داشبورد
- `packages/shared`: ثابت‌ها و تایپ‌های مشترک
- `packages/ui`: توکن‌ها و اجزای پایهٔ طراحی

## قابلیت‌های فاز یک که پیاده‌سازی شده‌اند

- Access/Refresh JWT و Refresh Cookie امن
- Logout و `GET /auth/me`
- Role Policy دقیق برای نقش‌های پنل
- محدودیت تلاش Login
- پاسخ استاندارد خطاهای API
- کاتالوگ عمومی با جستجو، فیلتر، برند، خودرو و Pagination
- صفحات SEOمحور محصول، دسته‌بندی، خودرو و میاندوآب
- Sitemap و Robots
- مدیریت محصول، برند، خودرو، تیپ، تصویر و Media Library
- قوانین موجودی اتمی و Ledger
- بارکد EAN-13 و اسکنر پنل
- داشبورد خلاصهٔ محصولات و انبار
- مدل‌های Refresh Token، Audit Log و Invoice در Prisma
- Health و Readiness probe برای API و PostgreSQL
- Docker Compose برای PostgreSQL و Redis

## خروجی‌های تکمیل‌شدهٔ فاز یک

- Migrationهای Prisma برای تمام مدل‌های فاز یک و Seed قابل تکرار برای کاربر مدیر و داده‌های مرجع.
- Refresh Token با ذخیرهٔ hash در جدول `refresh_tokens`، Rotation اتمیک، انقضا، ابطال و Cookie امن.
- CRUD مدیریتی محصول با اعتبارسنجی، SEO خودکار/قابل ویرایش، Soft Delete، Restore و Audit.
- Ledger موجودی برای موجودی اولیه، خرید، اصلاح، انتقال و ثبت Audit در مسیر تراکنشی.
- API عمومی امن و صفحات SEOمحور محصول، دسته‌بندی، خودرو و موقعیت محلی.
- Media Library با محدودیت نوع/حجم، تبدیل WebP، انتخاب تصویر اصلی و حذف رسانه.
- تست‌های خودکار API و پکیج مشترک، TypeScript strict و Build تولیدی هر سه اپ.

## نمایش محصولات بیشتر در سایت

- فهرست اصلی، دسته‌بندی‌ها و صفحات خودرو ابتدا **۲۸ محصول** را روی سرور رندر می‌کنند.
- «نمایش محصولات بیشتر» در هر کلیک فقط **۲۸ محصول بعدی** را دریافت و به فهرست اضافه می‌کند؛ آخرین مرحله ممکن است کمتر از ۲۸ مورد باشد. تمام کاتالوگ یک‌جا دریافت نمی‌شود.
- جست‌وجو، خودرو، دسته، برند و فیلتر موجودی در دریافت‌های بعدی حفظ می‌شوند. تغییر فیلتر، فهرست را از ابتدا شروع می‌کند. شمارندهٔ تعداد نمایش‌داده‌شده و حالت دریافت/تلاش مجدد نیز وجود دارد.
- درخواست مرورگر به مسیر هم‌مبدأ `/catalog/products` در Next.js می‌رود؛ نشانی داخلی `API_URL` فقط سمت سرور استفاده می‌شود. تنها فیلدهای موردنیاز کارت محصول به مرورگر فرستاده می‌شوند.
- دکمه یک لینک واقعی به صفحهٔ بعد هم هست؛ بدون JavaScript، صفحات شماره‌دار ۲۸تایی قابل بازشدن‌اند. URLهای صفحه‌بندی، لینک قبل/بعد و canonical هر صفحه حفظ شده‌اند.
- هنگام بازگشت از محصول، علاوه بر BFCache مرورگر، بازیابی فهرست و اسکرول با `sessionStorage` انجام می‌شود؛ این بازیابی برای آخرین فهرست، تا ۱۵ دقیقه، حداکثر ۵۶۰ محصول و یک مگابایت است و به دسترسی به حافظهٔ مرورگر وابسته است. تغییر فیلتر یا تغییر فهرست اولیه، کش نامرتبط را بازیابی نمی‌کند.

## اسلایدر تصاویر فروشگاه

مسیر مدیریت: **تنظیمات ← اطلاعات فروشگاه ← اسلایدر تصاویر فروشگاه**.

- حداکثر ۱۰ تصویر JPG/PNG/WebP تا ۵ مگابایت؛ افزودن تصویر، توضیح جایگزین، تغییر ترتیب با دکمه‌های قبل/بعد و حذف از اسلایدر. تغییرات با «ذخیره تنظیمات» منتشر می‌شوند؛ کش اطلاعات سایت حداکثر یک دقیقه است.
- تصاویر روی سرور واقعاً decode و با اعمال چرخش EXIF و حذف متادیتا به WebP با حداکثر ابعاد ۱۶۰۰×۱۲۰۰ تبدیل می‌شوند. تصویر افقی ۱۶۰۰×۹۰۰ پیشنهاد می‌شود؛ پرکردن کادر ممکن است لبه‌ها را ببرد.
- جایگزین ویدئوی معرفی فروشگاه در صفحهٔ اصلی؛ در موبایل فقط اسلایدر داخل باکس سرمه‌ای با گوشه‌های گرد و ارتفاع ۱۷۰ تا ۲۲۰ پیکسل نمایش داده می‌شود. اطلاعات دسکتاپ و ویدئوهای اختصاصی محصولات دست‌نخورده‌اند.
- پخش خودکار هر ۵ ثانیه با حلقه، اندیکاتور قابل کلیک، سوایپ افقی، کلیدهای جهت‌نما و توقف/ادامه. حرکت خودکار با تنظیم کاهش حرکت دستگاه متوقف می‌شود؛ همچنین در تب مخفی، خارج از دید، هنگام hover ماوس و فوکوس صفحه‌کلید مکث می‌کند.
- اطلاعات مرتب‌شده در کلید JSON تنظیمات `store.slider` نگهداری می‌شود؛ نیازی به migration جدید نیست. API مدیریت همان مجوز manager موجود را دارد. `/public/meta` فقط اطلاعات عمومی اسلایدر را برمی‌گرداند.
- تا زمان افزودن تصاویر، جای‌نگهدار ساده نمایش داده می‌شود؛ ویدئوی قدیمی به‌عنوان fallback پخش نمی‌شود. حذف از اسلایدر فایل را پاک نمی‌کند؛ حذف دائمی از کتابخانهٔ رسانه، ارجاع آن را نیز از تنظیمات اسلایدر حذف می‌کند.
- Deploy، حد بدنهٔ درخواست مسیر API پنل را با حفظ تنظیمات TLS و محدودیت‌های بزرگ‌تر موجود، حداقل به ۶ مگابایت می‌رساند؛ شکست اعتبارسنجی Nginx باعث rollback همان تنظیمات می‌شود.

## پیامک مستقیم برای استعلام محصول

- دکمهٔ «پیامک» کنار تماس در کارت‌های محصول و کنار پیام‌رسان‌ها در صفحهٔ محصول، برنامهٔ پیامک دستگاه را با نام همان محصول و متن آمادهٔ استعلام موجودی/قیمت باز می‌کند.
- مقصد همان شمارهٔ اصلی ثبت‌شده در تنظیمات فروشگاه و استفاده‌شده برای تماس است؛ شماره باید قابلیت دریافت SMS داشته باشد. بدون شمارهٔ معتبر، دکمه نمایش داده نمی‌شود.
- شماره‌های فارسی/عربی نرمال می‌شوند و متن فارسی و خط‌های جدید در لینک `sms:` کدگذاری می‌شوند. قالب لینک متناسب با Android یا iOS/iPadOS انتخاب می‌شود.
- این قابلیت هیچ پیامکی خودکار ارسال نمی‌کند و از درگاه پیامکی سرور استفاده نمی‌کند؛ ویرایش و تأیید ارسال در برنامهٔ پیامک خود مشتری است. روی دسکتاپ یا دستگاه بدون برنامهٔ پیامک، پشتیبانی به سیستم‌عامل و برنامهٔ پیش‌فرض آن بستگی دارد.

## واترمارک تصاویر پست کانال‌ها

- هنگام انتشار محصول در کانال‌های تلگرام و بله (دستی یا خودکار)، تصویر ارسالی در بالا سمت چپ دارای آیکون سایت و نام فروشگاه است.
- خروجی مخصوص کانال همیشه یک قاب سفید `1200×1200` است. عکس محصول با حفظ نسبت طول و عرض و بدون برش داخل قاب قرار می‌گیرد؛ سپس واترمارک با اندازهٔ ثابت و فاصلهٔ ثابت ۲۴ پیکسل از بالا و چپ اضافه می‌شود. اندازهٔ متن و آیکون به رزولوشن عکس محصول وابسته نیست. این کار کیفیت جزئیات عکس کم‌وضوح را افزایش نمی‌دهد، ولی از کوچک‌شدن و افت وضوح واترمارک همراه آن جلوگیری می‌کند.
- نام و آیکون از تنظیمات `store.profile` خوانده می‌شوند: `name` و `faviconUrl`. اگر آیکون قابل استفاده نباشد، `logoUrl` و سپس نشان پیش‌فرض «س» استفاده می‌شود؛ نام پیش‌فرض «فروشگاه سلیم وند» است.
- نسخهٔ واترمارک‌دار در حافظه ساخته و به بله به‌صورت فایل ارسال می‌شود. برای تلگرام، یک کپی جدا در `uploads/channel-posts/` ذخیره و آدرس عمومی آن با JSON ارسال می‌شود؛ بنابراین آپلود multipart از مسیر پروکسی تلگرام عبور نمی‌کند. فایل اصلی، مسیر تصویر محصول، تصاویر سایت و کتابخانهٔ رسانه تغییر نمی‌کنند.
- مسیر `/uploads/channel-posts/` باید روی `PUBLIC_SITE_URL` بدون ورود یا محدودیت دسترسی برای سرورهای تلگرام قابل دریافت باشد؛ تنظیم `/uploads/` موجود در Nginx این مسیر را هم پوشش می‌دهد. فایل‌های این پوشه عمومی و مخصوص کانال هستند. نام فایل از هش محتوا ساخته می‌شود تا انتشار مجدد تصویر یکسان فایل‌های تکراری نسازد؛ تغییر تصویر یا برند فایل جدیدی می‌سازد. این کپی‌ها خودکار حذف نمی‌شوند و در صورت نیاز باید جداگانه مدیریت شوند.
- محصولات بدون تصویر همچنان به‌صورت متنی منتشر می‌شوند. اگر ساخت تصویر واترمارک‌دار شکست بخورد، تصویر اصلی بدون واترمارک به کانال ارسال نمی‌شود.
- این تغییر روی انتشارهای جدید اعمال می‌شود و پست‌های قبلی کانال را ویرایش نمی‌کند.

## انتشار گروهی در کانال‌ها

در صفحهٔ **محصولات → انتشار گروهی**، نوع انتخاب را مشخص کنید:

- همهٔ محصولات فعال و حذف‌نشده؛
- یک یا چند مدل خودرو؛
- یک یا چند دسته‌بندی (زیر‌دسته‌ها باید جداگانه انتخاب شوند)؛
- یک یا چند برند دارای قلم انبار فعال؛
- ترکیب حداقل دو گروه خودرو، دسته یا برند با «اشتراک» (همهٔ گروه‌ها) یا «اجتماع» (یکی از گروه‌ها).

در هر فهرست چندانتخابی، انتخاب‌ها با «یا» ترکیب می‌شوند. فیلترهای «فقط دارای موجودی» و
«فقط دارای تصویر» به نتیجه اضافه می‌شوند. مقصد می‌تواند تلگرام، بله یا هر دو باشد.
ابتدا «محاسبهٔ تعداد محصولات» و سپس «شروع انتشار گروهی» را بزنید.

انتشار در صف مستقل BullMQ و با worker انجام می‌شود؛ بستن مرورگر آن را متوقف نمی‌کند.
هر مرحله حداکثر **۱۰ محصول** دارد؛ محصولات و کانال‌های انتخاب‌شده به‌ترتیب ارسال می‌شوند،
بین محصولات ۱٫۵ ثانیه و بین مراحل **۳۰ ثانیه** مکث می‌شود. برای ۲۰۰ محصول، ۲۰ مرحله وجود دارد.
حتی با چند worker، هم‌زمان فقط یک نوبت گروهی اجرا می‌شود؛ صف پیامک فاکتورها مستقل است.

تعداد موفق، ناموفق و ردشده برای هر کانال، شمارهٔ مرحله، آخرین ۱۰۰ خطا و دکمهٔ توقف در همان
پنجره نمایش داده می‌شوند. توقف جلوی ارسال‌های بعدی را می‌گیرد؛ ارسال جاری ممکن است کامل شود.
فهرست محصولات هنگام شروع ثابت می‌شود و محصولات حذف یا غیرفعال‌شده پیش از ارسال رد می‌شوند.
چند سازگاری یا دستهٔ هم‌پوشان باعث تکرار محصول در یک نوبت نمی‌شود؛ ثبت عمدی نوبت جدید، انتشار جدید است.

پیشرفت هر کانال در Redis ثبت می‌شود. در بازیابی کار پس از توقف worker، ارسال تأییدشده تکرار
نمی‌شود؛ ارسالِ درحال‌انجام با نتیجهٔ نامشخص برای بررسی دستی علامت می‌خورد و خودکار دوباره
فرستاده نمی‌شود. خطاهای کانال مانع ادامهٔ محصولات بعدی نیستند. نگهداری پیشرفت در برابر
راه‌اندازی مجدد خودِ Redis به تنظیم persistence آن وابسته است.

حداکثر هر نوبت ۲۰٬۰۰۰ محصول و سقف معمول صف ۵ نوبت است. پیشرفت و فهرست شناسه‌های محصول جدا
نگهداری می‌شوند تا در هر به‌روزرسانی، کل فهرست بازنویسی نشود. خلاصهٔ کارهای پایان‌یافته و
ناموفق تا ۷ روز و حداکثر ۳۰ مورد از هر نوع نگهداری می‌شود؛ پنل ۲۰ مورد اخیر را نشان می‌دهد.

## چک‌لیست محیط مقصد

برای اجرای Migration/Seed و تست Integration در محیط مقصد، PostgreSQL و Redis باید در دسترس باشند؛ این مرحله در چک‌لیست Deploy جامع نهایی انجام می‌شود و در طول توسعه Deploy جداگانه‌ای لازم نیست.

## اجرا

پیش‌نیاز: Node.js 20 و pnpm 9.

```bash
pnpm install
cp .env.example .env
pnpm dev
```

آدرس‌ها:

- سایت: http://localhost:3000
- پنل: http://localhost:5173
- API: http://localhost:4000/api/v1/health
- Readiness: http://localhost:4000/api/v1/health/ready

راه سادهٔ راه‌اندازی کامل محیط محلی:

```bash
./scripts/setup-local.sh
```

این اسکریپت به‌صورت خودکار وابستگی‌ها، PostgreSQL، Redis، Prisma، Migration و Seed را اجرا می‌کند. در محیط فعلی فقط کافی است Docker در دسترس باشد.

برای اجرای دستی سرویس‌ها:

```bash
docker compose -f docker-compose.dev.yml up -d
```

## اعتبارسنجی

```bash
pnpm typecheck
pnpm build
pnpm test
```

تست‌های فعلی API روی Auth، Catalog، Dashboard، Inventory، Role Policy، Rate Limit، Exception Filter و Public Invoice Token متمرکز هستند.

## محدودیت فعلی محیط

اجرای Prisma Migration و تست Integration تا فراهم‌شدن PostgreSQL و دسترسی Prisma Engine انجام نمی‌شود. پس از اتصال سرور/دیتابیس، این مرحله باید در چک‌لیست Deploy جامع نهایی اجرا و تأیید شود.
