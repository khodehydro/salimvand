# سبدها (Baskets) — آدرس سه‌سطحی انبار

هر قلم موجودی (کالا × برند) **قفسهٔ خودش** و **سبدِ خودش** را دارد. این سند مدل داده، API،
رفتار پنل و قرارداد اپلیکیشن اندروید را توضیح می‌دهد.

## ۱ · مدل داده

درخت مکان‌ها (`locations`) دقیقاً سه سطح دارد:

```text
انبار (warehouse)      parentId = null        انبار اصلی، فروشگاه، انبار دوم …
  └ قفسه (shelf)       parentId = انبار       A-03، ۱.۱، …
      └ سبد (basket)   parentId = قفسه        سبد ۱، سبد ۲، …
```

`inventory_items` دو اشاره‌گر دارد:

| ستون         | معنا                                           |
| ------------ | ---------------------------------------------- |
| `locationId` | قفسه — همیشه همانِ قبل (سازگار با دادهٔ موجود) |
| `basketId`   | سبد — `null` یعنی کالا مستقیماً روی قفسه است   |

هر دو کلید خارجی `ON DELETE SET NULL` هستند: حذف یک قفسه یا سبد هرگز موجودی کالا را از بین
نمی‌برد، فقط آدرس آن را خالی می‌کند (و پنل تعدادِ جدا‌شده‌ها را گزارش می‌دهد).

Migration: `apps/api/prisma/migrations/20260926000000_inventory_baskets/migration.sql`
(افزودن مقدار `basket` به enum و ستون + ایندکس + FK — بدون نیاز به ساخت مجدد دیتابیس).

## ۲ · قواعد سرور

قواعد در یک جا پیاده شده‌اند: `apps/api/src/common/inventory/placement.ts`
(`resolvePlacement`) و همهٔ مسیرهای نوشتن از آن استفاده می‌کنند.

- سبد باید موجود و از نوع `basket` باشد؛ قفسه یا شناسهٔ ناشناس با خطای ۴۰۰ رد می‌شود.
- سبد باید متعلق به همان قفسهٔ قلم باشد: «سبد انتخاب‌شده متعلق به این قفسه نیست».
- اگر فقط سبد فرستاده شود، قفسه از والدِ سبد پر می‌شود.
- پاک کردن قفسه (`locationId: null`) سبد را هم پاک می‌کند (آدرس یکی است).
- درخت سه‌سطحی با `LocationService` محافظت می‌شود: سبد نمی‌تواند والد داشته باشد، قفسه نمی‌تواند
  داخل سبد یا داخل قفسهٔ دیگر باشد، و انبار همیشه سطح اول است.

## ۳ · API

| مسیر                                    | تغییر                                                                                       |
| --------------------------------------- | ------------------------------------------------------------------------------------------- |
| `GET /locations`                        | هر گره علاوه بر فرزندان، تعداد اقلامِ سبدی را هم برمی‌گرداند                                |
| `POST/PATCH/DELETE /locations`          | نوع `basket` پذیرفته و اعتبارسنجی می‌شود                                                    |
| `GET /locations?type=basket&parentId=…` | فقط یک سطح درخت (مثلاً سبدهای یک قفسه) — برای پیکرها                                        |
| `POST /inventory/items`                 | `basketId` اختیاری                                                                          |
| `PATCH /inventory/items/:id`            | `basketId` اختیاری (`null` = پاک کردن)                                                      |
| `POST /inventory/transfer`              | `basketId` مقصد اختیاری                                                                     |
| `GET /inventory/items`, `low-stock`     | هر قلم `basket` را هم دارد                                                                  |
| `GET /inventory/items?locationId=`      | فیلتر با درخت هماهنگ است: قفسه شامل سبدهایش هم می‌شود و سبد فقط کالاهای خودش را برمی‌گرداند |
| `POST /products`, `PATCH /products/:id` | `items[].basketId` / `inventory.basketId`                                                   |
| `GET /sync/bootstrap`, `GET /sync/pull` | `basketId` در snapshot قلم موجودی                                                           |
| خروجی اکسل/CSV گزارش‌ها                 | ستون سبد کنار قفسه                                                                          |

## ۴ · پنل مدیریت

- **انبار و موجودی ← قفسه‌ها و سبدها**: سه بخش «انبارها»، «قفسه‌ها» و «سبدها». سبد با نام، کد و
  قفسهٔ والد ساخته می‌شود و تعداد کالاهای داخل آن نمایش داده می‌شود.
- **کارت قلم**: آدرس کامل («انبار · قفسه · سبد») و انتقال هم‌زمان به قفسه و سبد مقصد.
- **محصولات → قلم‌ها، قیمت و موجودی**: برای هر قلم، انتخاب قفسه و سبدِ همان قفسه.
- **ثبت محصول**: هر قلم انبار می‌تواند همان ابتدا سبد بگیرد.
- **برچسب قفسه‌ها و سبدها**: چاپ برچسب برای هر دو سطح (نام سبد + نام قفسهٔ آن).

## ۵ · قرارداد اندروید

`locations` در Bootstrap شامل سبدها هم هست (`type = basket`)؛ برای نمایش آدرس یک قلم،
`locationId` و `basketId` را به نام حل کنید:

```text
انبار اصلی · A-03 · سبد ۲
```

عملیات آفلاین:

```jsonc
// جابه‌جایی کالا به قفسه/سبد دیگر
{ "type": "inventory.transfer",
  "payload": { "itemId": "...", "locationId": "shelf-id", "basketId": "basket-id" } }

// ویرایش metadata (قیمت/قفسه/سبد/بارکد/برند)
{ "type": "inventory.update_metadata",
  "payload": { "itemId": "...", "locationId": "shelf-id", "basketId": "basket-id" } }

// ثبت محصول جدید با قلم انبار
{ "type": "product.create",
  "payload": { "name": "...", "categoryId": "...",
    "items": [{ "brandId": "...", "salePrice": "2450000",
                "locationId": "shelf-id", "basketId": "basket-id",
                "initialQuantity": 10 }] } }
```

`basketId` اختیاری است؛ حذف فیلد یعنی «تغییر نکند» و `null` یعنی «بدون سبد».
جزئیات کامل در `docs/android-api-catalog.md`.

## ۶ · پشتیبان‌گیری و بازیابی

`products.json` برای هر قلم علاوه بر `locationCode`، مسیر کامل جایگذاری را هم ذخیره می‌کند
(`locationPath`, `basketPath`)، چون کد سبدها در قفسه‌های مختلف تکرار می‌شود
(«سبد ۲» زیر هر قفسه). بازیابی با همین مسیرها سبد را دقیقاً در قفسهٔ خودش می‌سازد.
بکاپ‌های قدیمی (بدون این فیلدها) همچنان با کلید قدیمی «کد والد > کد» بازیابی می‌شوند.
