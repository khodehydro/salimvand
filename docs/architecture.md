# معماری اجرایی فروشگاه سلیم‌وند

این فایل خلاصهٔ اجرایی سند مادر معماری است. منبع منطق کسب‌وکار سند معماری ارسالی کارفرماست؛ در تعارض‌ها امنیت، داده و این قواعد بر ظاهر اولویت دارند.

## محصولات و موجودی

- `Product` فقط رکورد کاتالوگ است؛ `InventoryItem` ترکیب محصول و برند است.
- موجودی cached است و تنها `InventoryService` اجازهٔ تغییر آن را دارد.
- هر تغییر باید در همان تراکنش دیتابیسی یک `InventoryTransaction` غیرقابل‌تغییر بسازد.
- اصلاح دستی بدون دلیل رد می‌شود؛ فروش، خرید، مرجوعی و انتقال همگی ledger دارند.
- محصول، مشتری و تأمین‌کننده soft-delete می‌شوند؛ فاکتور صادرشده حذف یا ویرایش نمی‌شود.
- پول `BIGINT` و برحسب ریال است؛ زمان در UTC ذخیره می‌شود و برای رابط شمسی نمایش داده می‌شود.

## سطح دسترسی

| نقش | دسترسی اصلی |
|---|---|
| `super_admin` | همهٔ ماژول‌ها، کاربران و تنظیمات امنیتی |
| `manager` | عملیات فروشگاه، گزارش و تنظیمات عملیاتی |
| `seller` | مشتری و فروش/فاکتور |
| `warehouse` | انبار، قفسه و تراکنش‌های موجودی |
| `accountant` | فاکتور، پرداخت، خرید و گزارش مالی |

همهٔ endpointهای مدیریتی باید JWT و policy نقش داشته باشند و خطاها از exception filter مرکزی عبور کنند.

## API عمومی

`GET /api/v1/public/products` فقط این موارد را برمی‌گرداند: نام، کد، تصویر، دسته، سازگاری خودرو، برند و وضعیت موجودی. قیمت خرید، قیمت فروش، تعداد دقیق، قفسه و هر دادهٔ داخلی ممنوع است. صفحهٔ عمومی قیمت ندارد و فقط به تلفن/تلگرام/بله هدایت می‌کند.

فیلترهای `q`, `categoryId`, `vehicleModelId`, `vehicleTrimId`, `brandId`, `inStock` و `page` قابل اشتراک در URL هستند. وضعیت نمایش محاسباتی است: override به‌زودی/توقف، سپس موجود کم، موجود و ناموجود.

## قرارداد UI

- RTL کامل، فونت Vazirmatn و fallback تاهوما.
- تمام رنگ‌ها از توکن‌های `packages/ui` می‌آیند؛ استفاده از hex در صفحه‌ها ممنوع.
- پوسته با `data-theme="light|dark"` تغییر می‌کند.
- شعاع دکمه ۱۰، کارت ۱۴ و badge به‌صورت pill است.
- اعداد رابط فارسی؛ code، barcode و شماره‌های فنی LTR و monospace.
- هر صفحه قبل از تحویل در موبایل و دسکتاپ و هر دو پوسته بررسی می‌شود.

## نقشهٔ راه اجرایی

1. **فاز صفر:** مدل Prisma، پکیج shared، design system، احراز هویت، seed و زیرساخت اجرا.
2. **فاز یک:** کاتالوگ عمومی، فیلترها، محصولات، رسانه و انبار.
3. **فاز دو:** فروش، پرداخت چندروشی، ledger فروش، فاکتور عمومی امن، PDF/QR و پیامک.
4. **فاز سه:** داشبورد، گزارش سود، جستجوی سراسری و command palette.
5. **فاز چهار:** تنظیمات، سلامت integrationها، backup قابل بازیابی.
6. **فاز پنج:** تست پذیرش، hardening، استقرار و بازبینی نهایی light/dark.

## اجرای محلی

```bash
corepack enable
pnpm install
cp .env.example .env
docker compose -f docker-compose.dev.yml up -d
pnpm --filter @salimvand/api prisma:generate
pnpm --filter @salimvand/api prisma:migrate
pnpm --filter @salimvand/api prisma:seed
pnpm dev
```

> برای محیط CI باید `pnpm` نسخهٔ تعریف‌شده در `package.json` با Corepack فعال شود. هیچ secret یا فایل backup در repository قرار نمی‌گیرد.
