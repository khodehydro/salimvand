## تعریف وضعیت‌ها

- **اسکلت کد:** مسیر، مدل یا کامپوننت اولیه وجود دارد؛ سناریوی واقعی کامل نیست.
- **پیاده‌سازی کاربردی:** سناریو در API/UI قابل استفاده است و خطاهای اصلی مدیریت شده‌اند.
- **آمادهٔ Production:** سناریو با امنیت، Audit، تست و عملیات Production پوشش دارد.
- **تکمیل مطابق سند:** هم رفتار و هم ظاهر، Responsive، RTL، هر دو Theme و Acceptance Criteria سند را پوشش می‌دهد.

## نتیجهٔ اجرایی فعلی

نسخهٔ موجود یک هستهٔ قابل اجراست، نه محصول نهایی مطابق سند. API، دیتابیس و Deploy راه افتاده‌اند؛ اما Website و CMS هنوز بخش زیادی از نماها و گردش‌کارهای سند را ندارند. ادعای تکمیل ۱۰۰٪ پذیرفته نیست تا تست‌های انتهابه‌انتها و بازبینی بصری انجام شود.

## اولویت اجرای تکمیل

1. تثبیت Design System در `packages/ui` و حذف توکن‌های پراکنده.
2. بازسازی Website طبق UI Reference با SSR، فیلتر URL، SEO و Responsive کامل.
3. تکمیل مدل/APIهای مشتری، تأمین‌کننده، خرید، مرجوعی و تنظیمات.
4. ساخت CMS Shell واقعی و تکمیل Dashboard، Sales، Product، Warehouse، Reports و Settings.
5. تولید PDF/QR، صف پیامک/تلگرام و Backup قابل بازیابی.
6. افزودن تست‌های API/Integration/UI/E2E و اجرای Acceptance Matrix.
7. فقط پس از عبور همهٔ معیارها: Build، Deploy و گزارش نهایی Production.

## تصمیم‌های لازم‌الاجرا

- Website عمومی هیچ قیمت، قفسه، قیمت خرید یا دادهٔ داخلی نمایش نمی‌دهد.
- هر تغییر موجودی باید در تراکنش اتمی و Ledger ثبت شود.
- فاکتور صادرشده Immutable است؛ اصلاح فقط با Payment/Return/Void دارای Audit انجام می‌شود.
- حذف داده‌های اصلی Soft Delete است.
- همهٔ پول‌ها Integer ریال و زمان‌های ذخیره‌شده UTC هستند.
- UI کاملاً RTL، فونت Vazirmatn، اعداد فارسی و کدها LTR monospace است.
- رنگ‌ها فقط از توکن‌ها می‌آیند و هر صفحه Light/Dark و Desktop/Mobile دارد.
- طبق الزام تحویل این پروژه، صفحات اختصاصی محصول/دسته/خودرو/موقعیت محلی حفظ می‌شوند؛ حتی اگر خلاصهٔ معماری Website را دو مسیر اصلی توصیف کرده باشد.
